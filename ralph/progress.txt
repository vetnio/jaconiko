## Codebase Patterns
- Schema files are in `src/lib/db/schema/` with barrel export via `index.ts` (wildcard re-exports)
- Use `pgTable` from `drizzle-orm/pg-core` for table definitions, `relations` from `drizzle-orm` for relations
- UUIDs use `uuid("id").defaultRandom().primaryKey()` pattern
- User FK is `text` type (not uuid) referencing `user.id`
- Timestamps use `timestamp("col").notNull().defaultNow()`
- Foreign keys use inline `.references(() => table.col, { onDelete: "cascade" })` syntax
- Drizzle snapshot is out of sync (0001_snapshot.json missing dashboard tables) — use `drizzle-kit push` for schema changes or `--custom` for manual migration SQL
- `drizzle-kit generate` may prompt interactively about enums — use `--custom` flag to bypass
- Always use `IF NOT EXISTS` / `CREATE TABLE IF NOT EXISTS` in custom migration SQL for safety
- API routes use `auth.api.getSession({ headers: await headers() })` for auth, route params are Promises that must be awaited
- Workspace membership verified by looking up project → project.workspaceId → `getMembership(userId, workspaceId)`
- Validation schemas go in `src/lib/validations.ts` using Zod, use `.safeParse()` pattern
- Widget type enum values: `chart_bar`, `chart_line`, `chart_pie`, `data_table`, `stat_kpi`
- Use `db.transaction(async (tx) => { ... })` for multi-table inserts
- Use `notInArray` from `drizzle-orm` when deleting rows not in a provided list of IDs
- PATCH routes for entities with child rows: separate existing (with id) vs new (without id) items, delete removed, update existing, insert new — all in a transaction
- Use `.onConflictDoNothing()` for idempotent inserts (e.g., bookmarks with unique constraints)
- Use `innerJoin` for fetching related data across tables in a single query (e.g., bookmarks + dashboard details)
- Dashboard chart components are in `src/components/dashboard/` — `bar-chart.tsx`, `line-chart.tsx`, `pie-chart.tsx`
- Chart components accept `{ data: Record<string, unknown>[], config?: {...} }` — config is optional with sensible defaults (auto-detects keys from data)
- Chart colors use CSS custom properties: `var(--primary)`, `var(--success)`, `var(--warning)`, `var(--destructive)`, `var(--accent-foreground)`
- Recharts `Pie` label render prop types require optional fields (`name?: string, percent?: number`) to satisfy `PieLabelRenderProps`
- All chart components use `"use client"` directive (Recharts requires browser APIs)
- Dashboard widget components (data-table, stat-card) are in `src/components/dashboard/` alongside chart components
- React hooks must be called before any early return — structure: hooks → useMemo → early return guard → event handlers → JSX
- AI tools are defined in `src/lib/chat/tools.ts` via `createCodebaseTools()` which receives context (installationId, repoFullName, defaultBranch, dbConnection?, dashboard) and is called from `src/app/api/chat/route.ts`
- To add new AI tools: add tool to the return object in `createCodebaseTools()`, add any new context params to `CreateCodebaseToolsOptions` interface, pass them from `route.ts`
